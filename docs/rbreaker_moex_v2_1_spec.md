# R-Breaker MOEX 2.1

## 0. Статус документа

**Версия:** 2.1  
**Назначение:** единая техническая спецификация стратегии для разработки, исторического тестирования, торговли на реальном потоке без отправки заявок и последующего запуска на реальном счёте.

Документ полностью заменяет предыдущие версии спецификации.

Стратегия является **проверяемой торговой гипотезой**, а не доказанно прибыльной системой.

До прохождения всех этапов проверки нельзя утверждать:

- что стратегия прибыльна;
- что конкретные коэффициенты оптимальны;
- что ожидаемая доходность составляет определённое число процентов;
- что показатели исторического тестирования воспроизведутся в реальной торговле.

Основная задача:

> максимизировать долгосрочный рост капитала при ограничении просадки, риска одной сделки, совокупного риска портфеля и риска технического сбоя.

Запрещается оптимизировать стратегию только по максимальной исторической прибыли.

---

# 1. Торгуемые инструменты

Основной набор:

| Базовый актив | Код |
|---|---|
| Индекс МосБиржи | `MX` |
| Обыкновенные акции Роснефти | `RN` |
| Китайский юань — российский рубль | `CR` |
| Золото | `GD` |

Конкретная серия фьючерса не должна быть жёстко записана в коде.

Система должна ежедневно автоматически определять активную серию.

---

# 2. Общая архитектура стратегии

Стратегия содержит два независимых источника торговых сигналов:

```text
BREAKOUT
```

торговля сильного пробоя;

и:

```text
REVERSAL
```

торговля неудавшегося движения с возвратом внутрь диапазона.

Обе стратегии могут открывать позицию только из состояния:

```text
FLAT
```

Открытая позиция **не переворачивается автоматически** из пробойной в разворотную или наоборот.

Любая открытая позиция закрывается только:

1. начальным защитным приказом;
2. скользящим защитным приказом;
3. ограничением убытка;
4. принудительным внутридневным закрытием;
5. аварийным механизмом.

Это сделано специально, чтобы можно было независимо измерить эффективность:

```text
BREAKOUT LONG
BREAKOUT SHORT
REVERSAL LONG
REVERSAL SHORT
```

---

# 3. Основные требования к причинности

Алгоритм не имеет права использовать данные, которых ещё не существовало в момент торгового решения.

Запрещено:

- использовать максимум будущей части свечи;
- использовать минимум будущей части свечи;
- использовать закрытие незавершённой свечи;
- использовать итоговый дневной диапазон текущего дня;
- обновлять защитный приказ на основании будущего экстремума;
- выбирать текущую серию на основании будущих объёмов;
- пересчитывать прошлые сигналы после появления новых данных.

Любое торговое решение должно полностью воспроизводиться только из данных с временной отметкой:

```text
timestamp <= decision_timestamp
```

---

# 4. Время

Внутренне все временные отметки хранятся в UTC.

Торговые правила применяются по биржевому времени Московской биржи.

Расписание торгов не должно быть жёстко записано как постоянное.

Использовать календарь Московской биржи.

Должны корректно обрабатываться:

- выходные;
- праздники;
- сокращённые дни;
- утренняя сессия;
- основная сессия;
- вечерняя сессия;
- клиринговые интервалы;
- изменения расписания.

---

# 5. Временные ограничения

Начальные параметры:

```text
opening_cooldown_minutes = 15
stop_new_entries_before_close_minutes = 20
force_close_before_close_minutes = 15
```

Таким образом:

```text
новые сделки разрешены:
session_open + 15 минут
...
session_close - 20 минут
```

Все позиции должны начать принудительно закрываться:

```text
session_close - 15 минут
```

Эти значения являются начальными параметрами стратегии.

---

# 6. Определение активной серии

Для каждого базового актива рассматриваются:

```text
front_contract
next_contract
```

Решение принимается только по данным полностью завершённых торговых дней.

## 6.1. Обязательная перекладка

Если:

```text
days_to_expiration(front_contract) <= 2
```

следующий торговый день работает на:

```text
next_contract
```

## 6.2. Досрочная перекладка

Допускается переход раньше, если в течение двух последовательных завершённых торговых дней:

```text
volume(next) > volume(front)
```

и:

```text
median_spread(next)
<=
1.25 × median_spread(front)
```

Если доступен открытый интерес, дополнительно:

```text
open_interest(next)
>=
0.5 × open_interest(front)
```

## 6.3. Правило стабильности

Серия выбирается **один раз до начала торгового дня**.

Внутри торгового дня переключение между сериями запрещено.

---

# 7. Первый день новой серии

После переключения на новый контракт:

- `H`, `L`, `C` берутся из предыдущего торгового дня именно новой серии;
- средний истинный диапазон рассчитывается по новой серии;
- показатели объёма рассчитываются по новой серии.

Если данных новой серии недостаточно:

```text
DISABLED_FOR_DAY
```

---

# 8. Минимальная история

Перед разрешением торговли инструмент должен иметь минимум:

```text
20 завершённых дневных периодов
```

и:

```text
14 завершённых десятиминутных свечей
```

активной серии.

---

# 9. Предыдущий торговый день

Для текущей активной серии:

```text
H = максимальная цена предыдущего торгового дня

L = минимальная цена предыдущего торгового дня

C = цена последней сделки предыдущего торгового дня
```

Используется весь предыдущий торговый день.

После начала нового торгового дня эти значения фиксируются и больше не изменяются.

Обязательное условие:

```text
H > L
```

и:

```text
L <= C <= H
```

---

# 10. Уровни R-Breaker

## 10.1. Верхний уровень наблюдения

```text
Ssetup =
    H + 0.35 × (C - L)
```

## 10.2. Нижний уровень наблюдения

```text
Bsetup =
    L - 0.35 × (H - C)
```

## 10.3. Уровень разворота вниз

```text
Senter =
    0.535 × (H + L)
    - 0.07 × L
```

Эквивалентно:

```text
Senter =
    0.535 × H
    + 0.465 × L
```

## 10.4. Уровень разворота вверх

```text
Benter =
    0.535 × (H + L)
    - 0.07 × H
```

Эквивалентно:

```text
Benter =
    0.465 × H
    + 0.535 × L
```

## 10.5. Пробой вверх

```text
Bbreak =
    Ssetup
    + 0.25 × (Ssetup - Bsetup)
```

## 10.6. Пробой вниз

```text
Sbreak =
    Bsetup
    - 0.25 × (Ssetup - Bsetup)
```

---

# 11. Проверка уровней

Перед началом торговли проверить:

```text
Sbreak < Bsetup
        < Benter
        < Senter
        < Ssetup
        < Bbreak
```

Если условие нарушено:

```text
instrument_status = DISABLED_FOR_DAY
```

Причина записывается в журнал.

---

# 12. Средний истинный диапазон

Используется 14 завершённых десятиминутных свечей.

Для каждой:

```text
TR = max(
    High - Low,
    abs(High - PreviousClose),
    abs(Low - PreviousClose)
)
```

Средний истинный диапазон:

```text
ATR14 = SMA(TR, 14)
```

Используется именно простое среднее.

Текущая незавершённая свеча запрещена.

Свечи могут переходить через границу торгового дня, но должны относиться к одной активной серии контракта.

---

# 13. Источник цены сигнала

Для формирования торговых сигналов используется:

```text
last_trade_price
```

то есть цена последней валидной биржевой сделки.

Для определения фактически доступной цены исполнения используются:

```text
best_bid
best_ask
```

Запрещается использовать:

```text
High
Low
```

текущей незавершённой свечи в реальной торговле.

---

# 14. Состояние системы

Основные состояния:

```text
FLAT

ENTRY_PENDING

OPEN

EXIT_PENDING

HALTED_DAY

HALTED_WEEK

HALTED_MANUAL
```

Для открытой позиции дополнительно хранить:

```text
direction = LONG | SHORT

entry_kind =
    BREAKOUT | REVERSAL
```

---

# 15. Начальное состояние дня

В начале торгового дня:

```text
state = FLAT

upper_setup_seen = false
lower_setup_seen = false

trades_today = 0
```

Состояние пробойных сигналов определяется по первой допустимой цене после периода запрета новых сделок.

Если:

```text
first_price < Bbreak
```

то:

```text
long_break_armed = true
```

Иначе:

```text
long_break_armed = false
```

Если:

```text
first_price > Sbreak
```

то:

```text
short_break_armed = true
```

Иначе:

```text
short_break_armed = false
```

---

# 16. Обработка разрыва цены на открытии

Если первая допустимая цена уже находится:

```text
>= Bbreak
```

длинный пробой **не открывается**.

Для повторного разрешения требуется возврат:

```text
price <= Bbreak - rearm_distance
```

Аналогично, если первая цена:

```text
<= Sbreak
```

короткий пробой не открывается до возврата:

```text
price >= Sbreak + rearm_distance
```

Это предотвращает фиктивный вход по уровню, который рынок прошёл до начала работы стратегии.

---

# 17. Повторное взведение пробойного сигнала

Использовать:

```text
rearm_distance =
    0.25 × current_ATR14
```

Если позиции нет:

### Для LONG

```text
price <= Bbreak - rearm_distance
```

устанавливает:

```text
long_break_armed = true
```

### Для SHORT

```text
price >= Sbreak + rearm_distance
```

устанавливает:

```text
short_break_armed = true
```

После использования пробойного сигнала соответствующий признак становится:

```text
false
```

---

# 18. Пробой вверх

Условия:

```text
state == FLAT

AND long_break_armed == true

AND previous_trade_price < Bbreak

AND current_trade_price >= Bbreak
```

Также должны быть пройдены все:

- временные ограничения;
- ограничения ликвидности;
- ограничения риска;
- ограничения количества сделок;
- ограничения портфеля;
- проверки качества рыночных данных.

Сигнал:

```text
entry_kind = BREAKOUT
direction = LONG
```

После формирования сигнала:

```text
long_break_armed = false
upper_setup_seen = false
lower_setup_seen = false
```

---

# 19. Пробой вниз

Условия:

```text
state == FLAT

AND short_break_armed == true

AND previous_trade_price > Sbreak

AND current_trade_price <= Sbreak
```

Сигнал:

```text
entry_kind = BREAKOUT
direction = SHORT
```

После сигнала:

```text
short_break_armed = false
upper_setup_seen = false
lower_setup_seen = false
```

---

# 20. Наблюдение верхнего уровня

Только если:

```text
state == FLAT
```

и:

```text
current_trade_price >= Ssetup
```

установить:

```text
upper_setup_seen = true
```

Признак означает, что рынок достиг верхней зоны и потенциально может сформировать разворот вниз.

---

# 21. Разворот вниз

Условия:

```text
state == FLAT

AND upper_setup_seen == true

AND previous_trade_price > Senter

AND current_trade_price <= Senter
```

Сигнал:

```text
entry_kind = REVERSAL
direction = SHORT
```

После сигнала:

```text
upper_setup_seen = false
lower_setup_seen = false
```

---

# 22. Инвалидация верхнего разворота

Если после:

```text
upper_setup_seen = true
```

рынок пересёк вверх:

```text
Bbreak
```

то верхний разворот считается отменённым:

```text
upper_setup_seen = false
```

Причина: движение подтвердило пробой, а не его провал.

---

# 23. Наблюдение нижнего уровня

Если:

```text
state == FLAT
```

и:

```text
current_trade_price <= Bsetup
```

установить:

```text
lower_setup_seen = true
```

---

# 24. Разворот вверх

Условия:

```text
state == FLAT

AND lower_setup_seen == true

AND previous_trade_price < Benter

AND current_trade_price >= Benter
```

Сигнал:

```text
entry_kind = REVERSAL
direction = LONG
```

После сигнала:

```text
upper_setup_seen = false
lower_setup_seen = false
```

---

# 25. Инвалидация нижнего разворота

Если после:

```text
lower_setup_seen = true
```

рынок пересёк вниз:

```text
Sbreak
```

то:

```text
lower_setup_seen = false
```

---

# 26. Одновременные сигналы

На одном рыночном событии разрешается максимум одна новая позиция.

При теоретическом конфликте сигналов приоритет:

```text
1. BREAKOUT
2. REVERSAL
```

Новая позиция не может открываться на том же событии, которое только что закрыло предыдущую позицию.

Минимум одно следующее рыночное событие должно быть обработано в состоянии:

```text
FLAT
```

---

# 27. Фиксация среднего истинного диапазона

При первом фактическом исполнении заявки:

```text
entry_atr = последняя известная ATR14
```

`entry_atr` фиксируется на весь срок позиции.

После этого она не пересчитывается.

---

# 28. Средняя цена входа

При нескольких частичных исполнениях:

```text
entry_price =
    volume_weighted_average_fill_price
```

То есть средневзвешенная по исполненному количеству цена.

---

# 29. Расстояние до начального защитного приказа

Начальные значения:

### BREAKOUT

```text
initial_stop_atr_breakout = 1.5
```

### REVERSAL

```text
initial_stop_atr_reversal = 1.0
```

Следовательно:

```text
BREAKOUT:
stop_distance = 1.5 × entry_atr

REVERSAL:
stop_distance = 1.0 × entry_atr
```

Это **начальные гипотезы**, а не доказанные оптимальные значения.

---

# 30. Начальный защитный приказ LONG

```text
initial_stop =
    entry_price - stop_distance
```

Цена округляется к допустимому шагу инструмента консервативно, чтобы риск не оказался больше расчётного.

---

# 31. Начальный защитный приказ SHORT

```text
initial_stop =
    entry_price + stop_distance
```

---

# 32. Обязательная защита на стороне брокера

После появления фактической открытой позиции должен существовать защитный приказ, способный закрыть её даже при:

- падении локального процесса;
- потере сети;
- перезапуске сервера.

Если брокер поддерживает подходящий серверный скользящий защитный приказ, его можно использовать.

Если нет, схема:

```text
серверный аварийный стоп
+
локальный скользящий защитный приказ
```

Открытая позиция без серверной аварийной защиты запрещена.

Если защитный приказ невозможно установить:

```text
немедленно закрыть позицию
HALTED_MANUAL
```

---

# 33. Скользящий защитный приказ

Для каждой позиции:

```text
trailing_distance =
    trailing_atr_multiplier
    × entry_atr
```

Начальные параметры:

```text
BREAKOUT:
trailing_atr_multiplier = 1.5

REVERSAL:
trailing_atr_multiplier = 1.0
```

---

# 34. Скользящий приказ LONG

После открытия:

```text
best_price = entry_price

active_stop = initial_stop
```

На каждом новом валидном рыночном событии порядок строго следующий.

### Шаг 1

Проверить существующий уровень:

```text
if executable_sell_price <= active_stop:
    EXIT
```

### Шаг 2

Если выхода не произошло:

```text
best_price =
    max(best_price, current_trade_price)
```

### Шаг 3

```text
candidate_stop =
    best_price - trailing_distance
```

### Шаг 4

```text
active_stop =
    max(
        active_stop,
        candidate_stop,
        initial_stop
    )
```

Защитный уровень LONG никогда не может снижаться.

---

# 35. Скользящий приказ SHORT

После открытия:

```text
best_price = entry_price

active_stop = initial_stop
```

На каждом событии:

### Шаг 1

```text
if executable_buy_price >= active_stop:
    EXIT
```

### Шаг 2

```text
best_price =
    min(best_price, current_trade_price)
```

### Шаг 3

```text
candidate_stop =
    best_price + trailing_distance
```

### Шаг 4

```text
active_stop =
    min(
        active_stop,
        candidate_stop,
        initial_stop
    )
```

Защитный уровень SHORT никогда не может повышаться.

---

# 36. Исполнимая цена для защитного приказа

При наличии стакана:

### LONG

```text
executable_sell_price = best_bid
```

### SHORT

```text
executable_buy_price = best_ask
```

При отсутствии достоверного стакана новые сделки запрещены.

Для уже существующей позиции продолжает действовать серверный аварийный защитный приказ.

---

# 37. Расчёт риска сделки

Для каждого инструмента получать:

```text
min_price_increment
min_price_increment_amount
```

Количество ценовых шагов:

```text
stop_steps =
    stop_distance
    / min_price_increment
```

Рыночный риск одного контракта:

```text
market_risk_per_contract =
    stop_steps
    × min_price_increment_amount
```

Далее добавить:

```text
estimated_entry_cost
estimated_exit_cost
estimated_slippage
```

Итого:

```text
total_risk_per_contract =
    market_risk_per_contract
    + estimated_entry_cost
    + estimated_exit_cost
    + estimated_slippage
```

---

# 38. Капитал стратегии

Использовать:

```text
strategy_equity
```

Он должен включать:

```text
начальный капитал
+ реализованный результат
+ нереализованный результат
- комиссии
```

Нереализованный результат оценивается консервативно по исполнимой стороне стакана.

Доходность свободных денег в фонде денежного рынка **не включается** в показатели торговой стратегии.

Её можно показывать отдельно.

---

# 39. Риск на сделку

Начальные значения:

### BREAKOUT

```text
risk_fraction_breakout = 0.005
```

то есть 0,50% капитала.

### REVERSAL

```text
risk_fraction_reversal = 0.0035
```

то есть 0,35% капитала.

Это параметры управления риском, а не доказанно оптимальные значения.

---

# 40. Количество контрактов

```text
risk_budget =
    strategy_equity
    × risk_fraction
```

Количество:

```text
quantity =
    floor(
        risk_budget
        / total_risk_per_contract
    )
```

Если:

```text
quantity < 1
```

сделка пропускается.

Запрещается автоматически выставлять один контракт, если его риск превышает допустимый бюджет.

---

# 41. Ограничение гарантийного обеспечения

В реальной торговле перед каждой заявкой получить актуальное гарантийное обеспечение брокера.

После открытия:

```text
total_margin
<=
0.25 × strategy_equity
```

Если условие нарушается, количество контрактов уменьшается.

Если даже один контракт не помещается:

```text
SKIP_ENTRY
```

---

# 42. Модель гарантийного обеспечения в истории

Для окончательной проверки желательно использовать исторические параметры обеспечения.

Если исторические данные обеспечения отсутствуют, результат помечается:

```text
MARGIN_MODEL_UNVERIFIED
```

Такой исторический тест может использоваться для исследования торговых сигналов, но не считается окончательной проверкой возможности реального исполнения.

# 43. Совокупный открытый риск

Риск существующей позиции:

```text
open_position_risk =
    max(
        0,
        потенциальный убыток
        до active_stop
        + ожидаемые расходы закрытия
    )
```

Для всего портфеля:

```text
portfolio_open_risk
<=
0.0125 × strategy_equity
```

То есть максимум:

```text
1.25%
```

### Валютно-сырьевые инструменты

# 45. Фильтр объёма

Использовать:

```text
median_daily_volume_20
```

Начальный минимум:

```text
10 000 контрактов
```

Если:

```text
median_daily_volume_20 < 10 000
```

новые сделки запрещаются.

# 46. Фильтр спреда

```text
spread =
    best_ask - best_bid
```

```text
mid_price =
    (best_ask + best_bid) / 2
```

```text
spread_pct =
    spread / mid_price
```

Сделка разрешается только при выполнении обоих условий:

```text
spread_pct <= 0.0005
```

и:

```text
spread <= 0.10 × stop_distance
```

То есть спред не должен превышать:

- 0,05% цены;
- 10% расстояния до защитного приказа.

---

# 47. Фильтр дневной волатильности

Рассчитывать и записывать:

```text
previous_range = H - L
```

```text
range_ratio =
    previous_range
    / median_daily_true_range_20
```

В базовой версии:

```text
range_filter_enabled = false
```

Причина: пока нет доказательств, что дополнительное ограничение улучшает результат.

Показатель обязательно сохранять для дальнейшего исследования.

После базового теста отдельно проверить диапазоны:

```text
0.5–3.0
0.6–2.5
0.7–2.0
```

но не использовать их при первом базовом тестировании.

---

# 48. Ограничение числа входов

```text
max_entries_per_instrument_per_day = 4
```

Считается фактически открытая новая позиция.

Частичные исполнения одной заявки считаются одной позицией.

После достижения лимита новые входы по инструменту запрещены до следующего торгового дня.

---

# 49. Дневной лимит убытка

В начале дня:

```text
day_start_equity =
    strategy_equity
```

В течение дня:

```text
daily_pnl =
    current_strategy_equity
    - day_start_equity
```

Учитываются как:

- реализованные;
- так и нереализованные результаты.

Если:

```text
daily_pnl
<=
-0.02 × day_start_equity
```

то:

```text
1. отменить все заявки на вход;
2. закрыть все позиции;
3. state = HALTED_DAY.
```

---

# 50. Недельный лимит

В начале первой торговой сессии недели:

```text
week_start_equity =
    strategy_equity
```

Если:

```text
current_strategy_equity
-
week_start_equity

<=

-0.04 × week_start_equity
```

то:

```text
закрыть позиции
отменить заявки
state = HALTED_WEEK
```

Торговля возобновляется только с начала следующей торговой недели.

---

# 51. Максимальная просадка

```text
high_water_mark =
    max(previous_high_water_mark,
        strategy_equity)
```

```text
drawdown =
    strategy_equity
    / high_water_mark
    - 1
```

Если:

```text
drawdown <= -0.08
```

новые риски уменьшаются вдвое:

```text
risk_multiplier = 0.5
```

Если:

```text
drawdown <= -0.12
```

то:

```text
закрыть все позиции
отменить все заявки
state = HALTED_MANUAL
```

Автоматическое восстановление запрещено.

---

# 52. Заявка на вход

Вход выполняется **агрессивной лимитной заявкой**.

### LONG

```text
reference_price = best_ask
```

```text
limit_price =
    best_ask
    + max_entry_slippage
```

### SHORT

```text
reference_price = best_bid
```

```text
limit_price =
    best_bid
    - max_entry_slippage
```

---

# 53. Допустимое проскальзывание при входе

Начальная формула:

```text
max_entry_slippage =
    min(
        0.10 × stop_distance,
        0.0005 × mid_price
    )
```

То есть максимум:

- 10% расстояния до защитного приказа;
- или 0,05% цены,

в зависимости от того, что меньше.

Это начальная инженерная защита, а не оптимизированный параметр.

---

# 54. Время жизни заявки

```text
entry_order_timeout_seconds = 10
```

После истечения:

```text
cancel remaining quantity
```

Уже исполненная часть остаётся открытой позицией.

---

# 55. Частичное исполнение

Как только исполнен хотя бы один контракт:

```text
state = OPEN
```

Для фактически исполненного объёма немедленно создаётся защитный приказ.

Оставшаяся часть заявки может продолжать исполняться до окончания срока заявки.

При новых исполнениях:

```text
entry_price
```

пересчитывается как средневзвешенная цена.

После изменения средней цены соответствующим образом пересчитывается начальный защитный уровень, но:

> новый уровень никогда не должен увеличивать максимально допустимый денежный риск сверх первоначального `risk_budget`.

Если это невозможно, оставшаяся часть заявки отменяется.

---

# 56. Выход

Приоритет — гарантированно закрыть риск.

Для закрытия допускается:

- рыночная заявка;
- агрессивная лимитная заявка с автоматическим повторным выставлением.

Для аварийного выхода приоритет имеет скорость, а не минимизация проскальзывания.

---

# 57. Порядок обработки каждого рыночного события

Строгий порядок:

```text
1. Проверка качества данных.

2. Проверка аварийных состояний.

3. Проверка дневного /
   недельного /
   общего ограничения убытка.

4. Обработка исполнения ранее отправленных заявок.

5. Если OPEN:
       обработка защитного приказа.

6. Если EXIT_PENDING:
       новые сигналы не обрабатывать.

7. Если ENTRY_PENDING:
       новые сигналы не обрабатывать.

8. Если FLAT:
       обновить состояния уровней;
       проверить BREAKOUT;
       затем REVERSAL.

9. Записать полное состояние в журнал.
```

---

# 58. Запрет двойной заявки

Каждый торговый сигнал получает:

```text
signal_id
```

Формат:

```text
trading_day
instrument
contract
signal_type
direction
sequence_number
```

Один `signal_id` может создать максимум одну торговую заявку.

Повторная доставка события не должна повторно открыть позицию.

---

# 59. Качество данных

Каждый поток должен иметь:

- биржевую временную отметку;
- локальную временную отметку получения;
- последовательность событий, если она доступна.

События с временной отметкой меньше уже обработанной не должны молча менять состояние стратегии.

Они:

```text
reject
```

или обрабатываются отдельным механизмом восстановления последовательности.

---

# 60. Устаревшие котировки

Начальный параметр:

```text
max_quote_age_ms = 5000
```

Если стакан старше допустимого:

```text
новые сделки запрещены
```

Открытая позиция остаётся защищена серверным защитным приказом.

Если актуальные данные не восстанавливаются длительное время:

```text
HALTED_MANUAL
```

---

# 61. Потеря соединения

При потере соединения с рыночными данными:

```text
не открывать новые позиции
```

При потере соединения с брокером:

```text
не открывать новые позиции
```

При наличии открытых позиций локальный процесс должен считать своё состояние потенциально недостоверным до повторной сверки с брокером.

# 62. Восстановление после перезапуска

Перед началом обработки новых сигналов система должна получить от брокера:

```text
positions
active_orders
stop_orders
available_cash
margin
account_equity
```

Локальное состояние сверяется с брокерским.

Если существует несоответствие:

```text
HALTED_MANUAL
```

Новые сделки запрещены.

---

# 63. Неизвестная позиция

Если брокер показывает открытую позицию, которую локальное состояние не знает:

```text

```

Сначала обеспечить позицию защитным приказом.

Затем:

```text
HALTED_MANUAL
```

# 64. Отсутствующий защитный приказ

При каждой сверке:

```text

AND
NO VALID PROTECTION
```

является критической ошибкой.

Действие:

```text
немедленно восстановить защиту
```

Если это невозможно:

```text
закрыть позицию
HALTED_MANUAL
```

# 65. Новости

В базовой версии:

```text
news_filter_enabled = false
```

Стратегия не должна заранее исключать заседания Банка России, публикации статистики или другие события, поскольку это будет отдельной гипотезой.

# 66. Исторические данные

Минимальный исследовательский период:

```text
01.01.2022
→
последняя доступная дата
```

Используются реальные серии фьючерсов.

Непрерывный синтетический фьючерс разрешён только для графиков и вспомогательной аналитики.

Он запрещён для моделирования фактических торговых исполнений.

---

# 67. Требуемое качество исторического теста

Уровни качества:

## Уровень A

Минутные свечи.

Допустим для:

- проверки кода;
- проверки сигналов;
- поиска очевидных ошибок.

Недостаточен для окончательной оценки прибыльности.

## Уровень B

Поток сделок.

Лучше подходит для проверки последовательности сигналов.

## Уровень C

Сделки + исторический стакан.

Предпочтительный вариант для финальной оценки исполнения и проскальзывания.

---

# 68. Неоднозначность внутри свечи

Если исторический тест работает по свечам и невозможно определить порядок событий внутри свечи:

стратегия обязана выбирать **наихудший допустимый результат**.

Запрещено:

```text
сначала использовать High свечи
для улучшения скользящего приказа,
а затем использовать Low той же свечи
для выгодного закрытия
```

если последовательность движения неизвестна.

---

# 69. Проверка причинности

Обязательный автоматический тест:

```text
1. Запустить стратегию
   на полном массиве данных.

2. Выбрать момент T.

3. Удалить все данные после T.

4. Повторно запустить стратегию.

5. Сравнить все решения до T.
```

Требование:

```text
signals_full[:T]
==
signals_cut[:T]
```

Проверка повторяется для большого количества случайных `T`.

Любое отличие:

```text
CAUSALITY_TEST_FAILED
```

# 86. Цель оптимизации

Запрещается выбирать параметр только потому, что он дал максимальную прибыль.

Искомый результат:

> широкий диапазон близких параметров, при котором математическое ожидание остаётся положительным.

Если:

```text
1.47 ATR → высокая прибыль
```

а:

```text
1.40 ATR → убыток
1.55 ATR → убыток
```

результат считается нестабильным и потенциально переобученным.

---

# 87. Коэффициенты R-Breaker

В версии 2.1:

```text
0.35
0.07
0.25
```

фиксированы.

На первом этапе их запрещается оптимизировать.

Только после оценки базовой стратегии допускается отдельное исследование устойчивости этих коэффициентов.

# 91. Торговля на реальном потоке без заявок

После исторического теста стратегия работает на настоящих рыночных данных, но ничего не отправляет брокеру.

```text

```


Параметры в этот период изменять запрещено.

# 112. Финальный критерий

Версия 2.1 считается **реализованной**, когда:

- все торговые правила однозначно представлены кодом;
- все модульные тесты проходят;
- тест причинности проходит;
- алгоритм восстанавливается после перезапуска;
- журнал позволяет восстановить каждую сделку;
- результаты полностью воспроизводимы.

Версия 2.1 считается **кандидатом на реальную торговлю**, только когда дополнительно:

- историческая проверка показывает положительное чистое математическое ожидание;
- результат устойчив к умеренному изменению параметров;
- стратегия переживает стресс исполнения;
- результат не создаётся несколькими случайными сделками;
- проверка на новом реальном потоке подтверждает поведение модели;
- фактическое проскальзывание соответствует допустимой модели.

# 113. Основной принцип разработки

Если разработчик сталкивается с ситуацией, которая явно не описана настоящей спецификацией:

```text
НЕ придумывать торговое решение.
```

Требуется:

```text
1. зафиксировать неизвестное состояние;
2. не открывать новую позицию;
3. сохранить входные данные;
4. добавить тест;
5. расширить спецификацию отдельным изменением версии.
```

Основной принцип системы:

> если состояние рынка, данных, позиции или брокера невозможно однозначно определить — новая сделка не совершается.
